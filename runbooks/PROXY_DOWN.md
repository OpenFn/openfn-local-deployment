# Proxy Down: the public address does not answer

> Shape: **standalone** (`v0.standalone`). On a clustered deployment delete this
> runbook.

> ✏️ **Template.** Replace every `example.org` and every `10.0.0.x`. Delete
> anything that does not apply to this deployment rather than leaving it
> unanswered.

Uptime Kuma shows **OpenFn (public) Down** while the serving stack's own
monitor is Up, or nothing from Kuma at all because the proxy server itself is
unreachable. The proxy is the single address everything sends to: while it is
down, nothing reaches OpenFn at either site, even though both stacks may be
fine.

## Diagnose, on the proxy server (`10.0.0.13`)

```sh
systemctl status nginx
sudo nginx -t
sudo openfn-switch status                    # where traffic goes, and whether that stack answers
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1/health_check
sudo tail -50 /var/log/openfn-proxy/error.log
```

| What you see | Likely cause | Do |
|---|---|---|
| `nginx -t` fails | a bad edit to a config file | `openfn-switch` keeps the previous upstream file as `openfn-upstream.conf.bak`; put it back and reload. Site config is regenerated by a managed run. |
| Nginx not running | crashed, or the server rebooted and it did not start | `sudo systemctl start nginx`; `sudo systemctl enable nginx` if it was not enabled |
| `openfn-switch status` says the stack does not answer | the stack, not the proxy | [STACK_DOWN.md](STACK_DOWN.md) |
| `curl` on the proxy answers 200 but the public address does not | DNS, the certificate, or the network in front of the proxy | `curl -vk https://openfn.example.org/health_check` from outside; check `certbot certificates` for expiry; check with whoever runs the network that 80 and 443 reach this host |
| The server is unreachable | power or network at the proxy site | this is the case the site was chosen to avoid; escalate to the host's owner. Nothing on the stacks needs doing. |

## If the proxy server is lost

Its configuration lives in the deployment inventory, not on the server. A
replacement at the same address is one managed run (`site.yaml`, proxy host
only); the first thing it does is point at the stack the inventory names as
serving, so run `openfn-switch` afterwards if that is not the one that was live.
The certificate is reissued by certbot. Uptime Kuma's monitors have to be
recreated in its UI (`/opt/openfn-kuma/README.md` lists them) unless its data
volume survived.

## Afterwards

Requests sent while the proxy was down were not stored by anything. Whether a
source system re-sends them is that system's behaviour.
